# Evaluation

The Evaluation framework provides comprehensive metrics and analysis for assessing RAG system performance. It integrates with RAGAS for automated evaluation and supports MLflow for experiment tracking.

## Overview

The evaluation framework processes query results generated by UnWeaver (or other RAG systems), calculates various metrics, and provides detailed analysis including timing statistics, token usage, and retrieval quality assessments.

## Entry Point

**Module**: `evaluation`

**Purpose**: Evaluate RAG system query results and generate metrics

**Usage**:
```bash
poetry run python -m evaluation \
  <working_dir> \
  --config <config_path>
```

**Arguments**:
- `working_dir`: Path to the working directory containing query results (e.g., `../unweaver/index_covidqa`)
- `--config`: Path to the configuration file (can be specified multiple times)
- `--extra`: Extra configuration values in `key:value` format

**What it does**:
1. Loads query results from the working directory
2. Extracts timing and token usage statistics
3. Calculates evaluation metrics using RAGAS
4. Aggregates metrics across runs and repeats
5. Logs results to MLflow (if configured)
6. Saves evaluation results to disk

### Run Script

**Script**: `run.sh`

**Purpose**: Automate evaluation for multiple datasets

**Usage**:
```bash
./run.sh
```

**What it does**:
- Iterates through configured datasets (covidqa, emanual, techqa)
- Runs evaluation for each dataset

## Configuration

The evaluation framework uses a JSON configuration file located at `configs/custom.json`.

### Configuration Structure

```json
{
  "remote_mlflow_uri": "http://mlflow-server:port/",
  "experiment_name": "UnweaverEval",
  "num_repeats": 3,
  "metrics": ["factual_correctness"],
  "llm": { ... },
  "embedder": { ... }
}
```

### Key Parameters

#### 1. General Settings

- `remote_mlflow_uri`: MLflow tracking server URI (set to `null` to disable MLflow)
- `experiment_name`: Name of the MLflow experiment
- `num_repeats`: Number of times to repeat evaluation for each run (for statistical significance)
- `metrics`: List of metrics to calculate (supported by RAGAS)

#### 2. LLM Configuration (`llm`)

```json
{
  "llm": {
    "base_urls": ["http://llm-server:port/v1"],
    "api_keys": [["your-api-key"]],
    "model": "openai/gpt-oss-120b",
    "timeout": 300,
    "max_retries": 10,
    "max_workers": 128
  }
}
```

**Key parameters**:
- `base_urls`: List of LLM API endpoints for evaluation
- `api_keys`: API keys for each endpoint
- `model`: Model name/identifier
- `timeout`: Request timeout in seconds
- `max_retries`: Maximum number of retry attempts for failed requests
- `max_workers`: Maximum number of concurrent workers

#### 3. Embedder Configuration (`embedder`)

```json
{
  "embedder": {
    "max_async": 8,
    "mode": "remote",
    "base_urls": ["http://embedder-server:port"],
    "api_keys": [["your-api-key"]],
    "model": "Qwen/Qwen3-Embedding-4B",
    "embedding_dim": 2560,
    "max_token_size": 32768,
    "batch_size": 1,
    "timeout": 300
  }
}
```

**Key parameters**:
- `max_async`: Maximum number of concurrent embedding requests
- `mode`: Embedding mode ("remote" or "local")
- `base_urls`: List of embedder API endpoints
- `api_keys`: API keys for each endpoint
- `model`: Embedding model name
- `embedding_dim`: Dimension of embeddings
- `max_token_size`: Maximum token size for input
- `batch_size`: Batch size for embedding generation
- `timeout`: Request timeout in seconds

## Evaluation Metrics

The framework supports various metrics through RAGAS integration:

### Supported Metrics

- `factual_correctness`: Measures the factual accuracy of generated answers
- `answer_relevance`: Assesses how relevant the answer is to the question
- `context_precision`: Measures the precision of retrieved context
- `context_recall`: Measures the recall of retrieved context
- `faithfulness`: Assesses how faithful the answer is to the retrieved context

### Custom Metrics

The framework also includes custom metrics defined in `evaluation_custom.py`:
- Binary metrics for null answer detection
- Non-null answer specific metrics

## Input Format

The evaluation framework expects query results in the following structure:

```
<working_dir>/
├── config.json                 # Index configuration
├── query_results/              # Directory containing query results
│   ├── <run_name>_results.json      # Query results for a run
│   └── <run_name>_query_config.json # Query configuration for a run
└── ... (other index files)
```

### Query Results Format

Each `<run_name>_results.json` file should contain a JSON object with question IDs as keys and result objects as values:

```json
{
  "question_id_1": {
    "question": "What is the treatment for COVID-19?",
    "gt_answer": "The treatment includes...",
    "gt_context": ["Context 1", "Context 2"],
    ...,
    "sys_retrieval_results": {
        "context": ["Context for retrieval method"],
        "metadata": {
            "retrieval_methods": ["method_name"],
            "anchor_chunks": ["chunk 1", ...],
            "anchor_nodes": ["node 1", ...],

        },
    ...,
    "sys_answer": "Answer of the retrieval system"
    }
  },
  ...
}
```

## Output Format

The evaluation framework generates several output files:

### 1. Aggregated Results

**File**: `<working_dir>/eval_results.json`

Contains aggregated metrics for each run, including:
- Mean and variance of metrics across repeats
- Token usage statistics
- Query timing statistics
- Number of samples evaluated

### 2. Individual Evaluation Results

**File**: `<working_dir>/query_results/individual_eval.pqt`

Parquet file containing individual evaluation results for each question, repeat, and run combination.

### 3. MLflow Logging

If MLflow is configured, the framework logs:
- Parameters: Index configuration, query configuration, retrieval parameters
- Metrics: All calculated metrics (mean and variance)
- Artifacts: Timing plots and figures
- Token statistics: Input/output token counts
- Query timing: Retrieval and generation times

## Evaluation Pipeline

The evaluation process follows these steps:

1. **Load Data**: Load query results from the working directory
2. **Extract Timing Metrics**: Profile indexing and query timing
3. **Load Index Config**: Load the index configuration snapshot
4. **Process Query Results**:
   - Load results for each run
   - Repeat evaluation `num_repeats` times for statistical significance
   - Extract token statistics and query times
5. **Calculate Metrics**:
   - Use RAGAS to calculate configured metrics
   - Calculate custom binary metrics
   - Aggregate metrics across repeats
6. **Dump Results**: Save results to disk
7. **Log to MLflow**: Log parameters, metrics, and artifacts to MLflow

## Configuration Override

You can override configuration values in multiple ways:

1. **Multiple config files**: Specify multiple `--config` arguments (later files override earlier ones)
2. **Extra values**: Use `--extra key:value` to override specific values

Example:
```bash
poetry run python -m evaluation \
  ../unweaver/index_covidqa \
  --config configs/custom.json \
  --extra num_repeats:5 \
  --extra metrics:factual_correctness,answer_relevance
```

## Performance Profiling

The framework includes performance profiling capabilities:

### Timing Metrics

- **Indexing Time**: Time taken to index documents
- **Query Time**: Time taken to answer questions
  - Retrieval time: Time to retrieve relevant documents
  - Generation time: Time to generate answers

### Token Usage

- **Input Tokens**: Number of tokens in the input (question + context)
- **Output Tokens**: Number of tokens in the generated answer
- **Total Tokens**: Sum of input and output tokens

### Plots

The framework generates timing plots that can be logged to MLflow:
- Indexing time distribution
- Query time distribution
- Token usage distribution

## Troubleshooting

### MLflow Connection Issues

- Ensure MLflow server is running and accessible
- Check `remote_mlflow_uri` in configuration
- Set to `null` to disable MLflow logging

### RAGAS Metrics Issues

- Ensure LLM and embedder are properly configured
- Check that API endpoints are accessible
- Verify API keys are correct
- Adjust timeout values if requests are timing out

### Memory Issues

- Reduce `num_repeats` to decrease memory usage
- Reduce `max_workers` for LLM
- Process results in batches if needed

### Missing Query Results

- Ensure query results are in the correct directory structure
- Check that `<run_name>_results.json` files exist
- Verify that results are in the correct JSON format

## Example Workflow

A complete evaluation workflow:

1. **Run UnWeaver** to generate query results:
```bash
cd unweaver
poetry run python -m unweaver.query \
  ../data/covidqa/questions.json \
  ./index_covidqa \
  --run_name test_run \
  --config configs/custom.json
```

2. **Evaluate Results**:
```bash
cd ../evaluation
poetry run python -m evaluation \
  ../unweaver/index_covidqa \
  --config configs/custom.json
```

3. **View Results**:
- Check `../unweaver/index_covidqa/eval_results.json` for aggregated metrics
- Check `../unweaver/index_covidqa/query_results/individual_eval.pqt` for detailed results
- View MLflow UI for visualizations and experiment tracking
