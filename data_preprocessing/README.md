# Data Preprocessing Module

This module handles the preprocessing of datasets for RAG systems. It downloads datasets from the RAGBench benchmark, organizes them into a structured file tree, and converts them to JSON format with metadata for use in downstream RAG applications.

## Overview

The data preprocessing module performs two main operations:

1. **Dataset Download & Organization**: Downloads datasets from Hugging Face and creates a structured file tree with individual documents
2. **JSON Conversion**: Converts the file tree to JSON format with metadata for each file and directory

## Supported Datasets

The module currently supports three datasets from the [RAGBench benchmark](https://huggingface.co/datasets/rungalileo/ragbench):

- **covidqa**: COVID-19 related question answering dataset
- **emanual**: Electronic manual documentation dataset
- **techqa**: Technical question answering dataset

## Installation

### Prerequisites

- Python 3.10 or higher
- Poetry (for dependency management)

### Setup

1. Install dependencies using Poetry:

```bash
cd data_preprocessing
poetry install
```

## Usage

### Quick Start

The easiest way to run the preprocessing is using the provided shell script:

```bash
./run.sh
```

This will process all datasets and save the output to the `../data/` directory.

### Manual Execution

You can also run the module manually with custom parameters:

```bash
poetry run python -m data_preprocessing.main --input <data_directory>
```

**Parameters:**
- `--input`: (required) Path to the directory where dataset subfolders will be created

### Example

```bash
poetry run python -m data_preprocessing.main --input ../data
```

## Output Structure

After running the preprocessing, the following directory structure will be created:

```
<data_directory>/
├── covidqa/
│   ├── files/                    # Original document files
│   │   ├── 000ac4934e279743.txt
│   │   ├── 00af4dd53914727b.txt
│   │   └── ...
│   ├── files_preprocessed/       # JSON metadata files
│   │   ├── file-<uuid>/
│   │   │   ├── file-<uuid>.json
│   │   │   └── part-<uuid>.txt
│   │   └── ...
│   └── questions.json            # Questions and ground truth
├── emanual/
│   ├── files/
│   ├── files_preprocessed/
│   └── questions.json
└── techqa/
    ├── files/
    ├── files_preprocessed/
    └── questions.json
```

### File Descriptions

#### `questions.json`

Contains the questions, ground truth contexts, and answers for each dataset. Structure:

```json
{
  "0": {
    "question": "What is the incubation period of COVID-19?",
    "gt_context": ["Document text...", "Document text..."],
    "gt_context_hashed": ["000ac4934e279743", "00af4dd53914727b"],
    "gt_answer": "The incubation period...",
    "everything": {...}
  }
}
```

#### `files/` Directory

Contains individual document files with hashed filenames (MD5 hash of content, first 16 characters).

#### `files_preprocessed/` Directory

Contains JSON metadata files for each document:

- **File metadata** (`file-<uuid>/file-<uuid>.json`):
  ```json
  {
    "id": "file-<uuid>",
    "type": "fs:file",
    "content": [
      {
        "id": "part-<uuid>",
        "path": "file-<uuid>/part-<uuid>.txt"
      }
    ],
    "name": "000ac4934e279743.txt",
    "path": "."
  }
  ```

- **Directory metadata** (for empty directories):
  ```json
  {
    "id": "dir-<uuid>",
    "type": "fs:directory",
    "name": "directory_name",
    "path": "relative/path"
  }
  ```

## Module Architecture

### Main Components

#### `main.py`
Entry point that orchestrates the preprocessing pipeline:
1. Initializes logging
2. Downloads and organizes datasets using `get_docs()`
3. Converts file trees to JSON format using `process_files()`

#### `tools/create_filetree.py`
Downloads datasets from Hugging Face and creates the initial file structure:
- Loads datasets from `rungalileo/ragbench`
- Deduplicates questions (removes duplicates generated by different LLMs)
- Creates individual document files with hashed filenames
- Generates `questions.json` with metadata

#### `tools/convert_filetree_to_json.py`
Converts the file tree to JSON format with metadata:
- Processes files and directories asynchronously
- Generates unique IDs for each file/directory
- Creates JSON metadata files with structure information
- Copies original files to the preprocessed directory

#### `docs.py`
Defines data classes for document metadata:
- `FileDoc`: Metadata for file documents
- `DirDoc`: Metadata for directory documents

#### `utils.py`
Utility functions:
- `init_logging()`: Configures logging
- `get_unique_id()`: Generates UUID-based unique identifiers
- `get_extension()`: Extracts file extensions

#### `literals.py`
Defines constants:
- `DATASET_NAMES`: List of supported dataset names

## Technical Details

### Asynchronous Processing

The file conversion process uses asynchronous I/O with `aiofiles` for efficient file operations. Multiple files are processed concurrently using `asyncio.gather()` with progress tracking via `tqdm`.

### File Hashing

Document files are named using the first 16 characters of their MD5 hash. This ensures:
- Unique filenames
- Content-based identification
- Easy reference between questions and documents

### Deduplication

Questions are deduplicated based on the `question` field to remove duplicates that may have been generated by different LLMs in the original dataset.

## Dependencies

- `datasets`: Hugging Face datasets library for downloading RAGBench
- `aiofiles`: Asynchronous file operations
- `tqdm`: Progress bars
- `more-itertools`: Additional iteration utilities
- `python-dateutil`: Date/time utilities

## Troubleshooting

### Common Issues

1. **Dataset download fails**: Ensure you have internet access and the Hugging Face datasets library is properly installed.

2. **Permission errors**: Make sure you have write permissions to the output directory specified with `--input`.

3. **Memory issues**: Large datasets may require significant memory. Consider processing datasets individually if needed.
